# Intent: Surface nixarchy plugins, Nixi and skill-backed help as palette rows

## Problem

#5 asked for nixarchy plugins, Nixi and skill-backed help to appear as palette rows. Research shows most of it **already exists**, because the palette renders nixarchy's merged menu (`$OMARCHY_PATH/default/omarchy/omarchy-menu.jsonc`, generated from nixarchy `modules/apps.nix`):

- **Plugin rows exist,** each guarded so it shows only when its plugin is enabled (`when: nixarchy-plugin --enabled <id>`), and search finds them. They cover herdr, devenv, GitHub Actions, GitLab Pipelines, podman, pkg (Install), and microvm with its list fallback. The distrobox and flatsnap rows are in nixarchy's current build and show up after a re-login.
- **The skill-backed "Ask" group exists:** `trigger.ask` with nine `nixarchy-ask <topic>` rows ("What's wrong?", "Make it faster", "Am I exposed?", "Disk is full", …), shown only when a default agent is set.
- **A generic "every enabled plugin is a row" provider would duplicate the curated rows** and lose their labels, aliases and fallbacks.

What is actually wrong or missing:

1. **Bug: hidden help rows leak into search.**
   - `providers/OmarchyMenu.qml:392` checks only a row's own `when`, not its parents'.
   - So with no default agent, "faster" still offers "Make it faster". It opens a terminal that just prints "No default agent is set".
   - Browsing hides the rows correctly, and so does Smart Match's catalog, which uses the parent-aware `catalogVisible`. Only search leaks them.
2. **Help topics can't be found in natural words.**
   - The nine Ask children have no aliases or descriptions.
   - Search requires every word to match, so "why is my system slow" finds nothing in the menu, and Smart Match skips queries starting with "why".
3. **Nixi has no proper menu row.** The only one is a hand-written, unguarded "Help" row that Nixi's installer put in the user file (`~/.config/omarchy/extensions/omarchy-menu.jsonc`).
4. **A bare `?` shows nothing.** After #4, `?` lifts Ask Nixi, but only when text follows it.
5. **The Ask topics launch the agent without confirmation.** They run the default agent with auto-approve flags, the same risk #4 guards with a confirm sheet.

## Proposed outcome

- **In search, a row whose parent is hidden stays hidden,** as when browsing. With no default agent, no Ask topic appears.
- **Help topics are found in plain words:** "system slow", "why is it slow", "hacked", "open ports", "disk full", "what changed" all find the right Ask row.
- **Nixi has a menu row** generated by nixarchy, shown only when the Nixi card is enabled (label "Nixi" / "Help", aliases help, how, nixi, tour, learn). It replaces the hand-written user-file row.
- **A bare `?` offers "Ask Nixi"** (open Nixi) when Nixi is enabled.
- **Ask topics that launch an agent ask first,** using the same confirm sheet and warning as #4.

## Affected users and systems

- **This repo:**
  - `providers/OmarchyMenu.qml`: the parent-guard fix and the confirm for Ask topics.
  - `providers/AiWeb.qml`: the bare `?`.
  - Tests for each.
- **nixarchy** (`modules/apps.nix`, data only): aliases and descriptions for the Ask children, and a guarded Nixi row. This is a separate nixarchy issue with its own artifacts, and no provider code.
- **Nixi's installer** should stop writing the unguarded "Help" row once nixarchy generates one. That is a nixi-nixarchy follow-up.

## Constraints

- **No generic plugin provider.** The curated menu rows stay the single source.
- **The parent-guard fix must reuse `MenuModel`'s own `when` evaluation**, the same one browsing and `catalogVisible` use, not a second implementation.
- **The confirm applies to rows that run the agent,** not to every menu action.
- **Depends on #4** (`?` and Ask Nixi). Branched from `feat/4-agent-handoff`, and rebased after #4 merges.

## Open questions

1. **How do we tell which Ask rows need a confirm?**
   Proposed: any menu row whose action starts `nixarchy-ask` or `omarchy-agent`. That's a small, explicit pattern list in `OmarchyMenu.qml`, extendable.
2. **Where does the aliases and Nixi-row data live?**
   Proposed: nixarchy `modules/apps.nix`, as the source of the menu. The palette only reads it.
3. **Which label does the Nixi row use?**
   Proposed: "Nixi", with aliases help, how and ask. "Help" stays an alias rather than the label, to avoid clashing with other help rows.
